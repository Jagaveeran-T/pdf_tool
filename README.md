# Free browser-based PDF tools

Image to PDF, JPG to PDF, Merge PDF, Split PDF and Compress PDF. Everything runs in the visitor's browser (pdf-lib, pdfjs-dist, Web Workers). Files are never uploaded. Static export for Cloudflare Pages.

## Quick start

```bash
nvm use                      # Node 20.9 or newer (see .nvmrc)
npm install
cp .env.example .env.local   # then fill in the three required values
npm run dev
```

Required before launch: `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_SITE_NAME`, `NEXT_PUBLIC_CONTACT_EMAIL`. Everything else is optional and **off by default** (AdSense, GA4, Sentry, contact form).

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` / `build` | Develop / static export into `out/` (also copies the pdf.js worker, writes `ads.txt`, `_redirects`, icons and OG images) |
| `npm test` | Vitest unit and integration tests (fixtures are generated automatically) |
| `npm run test:e2e` | Playwright against `out/` on desktop and Pixel 7 (needs `npx playwright install chromium`) |
| `npm run lhci` | Lighthouse CI against `out/` |
| `npm run screenshots` | Re-captures the real tool screenshots in `public/images` (run after `npm run build`, then build again) |
| `npm run check:launch` | Lists launch blockers: placeholder text, `*.pages.dev`, missing publisher ID or `ads.txt` line, and so on |

## Notes

- `robots.txt` is generated by `app/robots.ts`, so there is no `public/robots.txt` (a static file would conflict).
- Binary assets (icons, OG images, test fixtures, screenshots) are generated by scripts, not hand-made.
- Playwright is pinned to the version in `package.json` so the browser build matches CI.
- Read the AdSense steps in the implementation guide before you apply. Nothing here guarantees approval.
